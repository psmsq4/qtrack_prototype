### 설계서 5.2 chunk 배치·링크 규칙 (반영 완료)
- 배치: FORMAL_IN(this, 파라미터 순) → FORMAL_OUT → 호출 지점별 ACTUAL_IN(수신 객체 [this], 인자 순)·ACTUAL_OUT → BIND → FIELD_STORE/FIELD_LOAD → (UNKNOWN) → L2(LOCAL, PREDICATE). `GraphBuilder.assignIds`가 파라미터 i = chunk 시작 + i를 검사.
- 메서드 표: 정규화 시그니처 `pkg.Class#name(erased types)`로 한 번만 등록, 중복은 첫 정의만 쓰고 `duplicateSignatures`로 집계.
  독립 합성 메서드: XML(인터페이스 없음) `ns#id(parameterType)`, 내장 JDBC `Class#m$sqlN@Lx(java.lang.Object,…)`, SQL 파일 `file.sql#stmtN@Lx()`.
- ID 배정은 입력 순서(파일 경로 순)로 결정적이고 호출 순서와 무관. IR은 다른 메서드를 시그니처 문자열로만 참조하며 링크 단계에서 위치로 ARG_IN/RET_OUT 생성.
- span.i64 = fileId << 32 | 바이트 오프셋 (Java: tree-sitter 바이트, MyBatis: 원문에서 `#{…}`·`<문장` 위치를 찾아 선언 인코딩 기준 바이트, SQL 파일: 문장 시작). 줄 번호는 표시할 때 `SourceLines`가 계산.
- 검증: `AppendixTest.chunkLayoutRule`, 노드·간선 대조는 (메서드, 종류, 이름) 기준.

## 5. 미결 사항(설계서 14장)에 대한 프로토타입 선택
1. FR-SQ와 COL_DERIVES: **포함** (구현 완료).
2. 제어 의존: **포함, CONTROL_FLOW 상주 축약까지**. try/catch는 단순화(try당 합성 PREDICATE).
3. 카탈로그 형식: DDL, 표준 CSV, QT_META_POPULATOR 내보내기 모두 수용.
4. 데이터소스 매핑: YAML (`default`, `mappings[package, dataSource, schema]`).
5. 상주 CSR: 종류별 유지. 합성 200도메인에서 offsets 비중은 `stats`의 `memory.offsetsBytes`로 확인.
6. AIS 어댑터: 미구현 (Parquet 내보내기로 대체).
7. 라이브러리 요약: JDK 핵심 클래스 한정.

## 6. 알려진 한계
- 람다 본문은 순차 실행으로 근사, 람다 매개변수는 수신 객체 값(HEURISTIC). 익명 클래스·지역 클래스 본문 미분석.
- 가상 호출: 구체 클래스 수신이면 그 클래스(상위 포함) 메서드만, 하위 클래스 재정의는 보지 않음.
- `PreparedStatement.setXxx(i, v)` 바인드는 연결하지 않음(SQL 테이블·컬럼만 기록). JdbcTemplate는 인자 위치로 연결.
- MyBatis typeAlias(`resultType="Order"`) 해석 없음 → FQN만 DTO 프로퍼티 매핑.
- 동적 SQL `<foreach>`는 1회 전개, OGNL `test` 조건은 평가하지 않음.
- QT_META_POPULATOR의 물리 컬럼명 열은 소스에서 확정하지 못해 `OBJ_RMK2`를 기본값으로 둠 (`-Dqtrack.qtmeta.column=`).
- 증분 갱신(설계서 9장, D-04)은 Phase 3 — `delta/` 디렉터리만 예약.
- jtreesitter의 query 문자열에 비ASCII가 있으면 잘리는 현상 → 규칙 `.scm`의 `;` 주석 줄은 컴파일 전에 제거, 그 밖의 비ASCII는 오류로 알림.
